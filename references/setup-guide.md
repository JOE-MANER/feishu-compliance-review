# 配置引导：把「直接读飞书文档」功能配好（财务用户版）

**总原则**：技术操作全部由 AI 助手代劳（改电脑里的配置、安装法规资料库、测试），用户只需要在飞书里做两件事，每件事都是点几下。一次只引导用户做一个动作，每步完成后用一句话确认。

## 开始前先问两个问题（只问这两个）

1. 「你们平时用飞书办公吗？是用国内的飞书，还是海外版的 Lark？」（决定去哪个网站创建应用，后续步骤完全一样）
2. 「你有公司飞书的后台管理权限吗？如果没有，能找到 IT 同事或管理员帮忙拿一次钥匙吗？」（拿钥匙需要管理权限；个人测试企业自己就是管理员）

其余情况（电脑环境、文档新旧）助手自己检测处理，**不要问用户**。

## 用户动作一：拿一次「钥匙」（约 5 分钟，只需做一次）

钥匙 = 一串编号和密码，让合规小助手能连上你们的飞书。给用户的点击路径：

1. 电脑浏览器打开 `open.feishu.cn`（海外 Lark 则是 `open.larksuite.com`）
2. 右上角登录 → 进「开发者后台」→ 点「创建企业自建应用」，名字随便起（比如「合规小助手」）
3. 创建好后，进「凭证与基础信息」页面，把 **App ID** 和 **App Secret** 两串字符复制发给助手
   （找不到 App Secret 就点「查看/重置」，复制后发来即可）
4. 左侧「权限管理」→ 搜索「文档」→ 把带"读取"字样的云文档权限勾上
5. 左侧「版本管理与发布」→ 创建版本 → 申请发布（可用范围选自己就行）

如果是 IT 同事帮忙：把上面 1-5 步发给 IT，请他提供 App ID 和 App Secret 即可。

## 用户动作二：把合规小助手加进文档分享名单（每份新文档一次）

1. 打开目标文档 → 右上角「分享」
2. 搜索刚创建的应用名（如「合规小助手」）→ 添加 → 权限选「**可阅读**」
3. 完成后跟助手说「加好了」

## 以下由助手操作，用户不用动手（执行参考）

**写入电脑配置**：把钥匙存入 `~/.zcode/cli/config.json` 的 `mcp.servers`（已存在 lark-mcp 条目则更新）：

```json
"lark-mcp": {
  "type": "stdio",
  "command": "npx",
  "args": ["-y", "@larksuiteoapi/lark-mcp", "mcp", "-a", "<App ID>", "-s", "<App Secret>"],
  "timeoutMs": 120000
}
```

注意：App Secret 属于敏感凭证，写入后提醒用户「钥匙已存到你电脑的本地配置里，不会外传；如果要作废它，随时可以在飞书后台重置」。

**安装法规资料库**（可选，装了检索更快）：

```bash
git clone --depth 1 https://github.com/LawRefBook/Laws "<本 skill 目录>/laws"
```

（本目录没有 git 或网络受限时跳过，改为纯在线检索，不影响使用。）

**测试**：请用户重启会话后发一个已加分享的文档链接，能读出全文即配置成功。成功后告诉用户：「配好了！以后把文档链接发给我就行。新文档记得先在分享里加上合规小助手。」

## 常见问题（用大白话回答用户）

- **「说没有权限打开文档」** → 钥匙没问题，只是这份文档还没加分享名单。让用户做「用户动作二」。
- **钥匙填了但连不上** → 多半是 App Secret 复制不全或被重置过，请用户回后台重新复制一份。
- **「应用还没发布/没权限」** → 用户动作一的第 4、5 步没做完（勾权限、发布版本）。
- **搜索类功能用不了** → 属正常，这套流程靠文档链接读取，不需要额外配置；不要主动向用户解释 user token 之类的概念。
